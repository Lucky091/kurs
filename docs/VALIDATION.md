# Результаты проверки

Проверено в Linux x86_64: Python 3.12.14, Pygame 2.6.1, SDL 2.28.4.
Графического дисплея в облачной машине нет; использован видеодрайвер SDL dummy.
Тесты заменяют только окно и аудиоустройство, а не игровые алгоритмы.

```bash
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy python -m unittest discover -s tests -v
```

## Функциональный прогон настоящего боя

```bash
python tools/smoke_gameplay.py
```

Отдельный воспроизводимый скриптовой пилот использовал только направление
движения, обычную стрельбу и покупки за заработанные кредиты. Он не менял
здоровье, урон, таймеры или число врагов. Пройдено **шесть волн**; босс пятой
волны уничтожен, игра продолжилась на **волне 7**. Время симуляции — 168,26 с,
счёт — 9340. Повторный запуск дал тот же результат. Это проверяет взаимодействие
систем, но не заменяет оценку удобства управления человеком.

`python -m pip check` завершился успешно: конфликтов зависимостей нет.
ZIP проверен по CRC, распакован в новую временную папку; оттуда выполнены
запуск из `/tmp` без аудио и полный прогон шести волн — оба с кодом 0.
Генератор `tools/generate_assets.py` выполнен; все поставляемые PNG и WAV созданы.
Файл установки облачной среды выполнен после установки повторно: существующие
зависимости корректно переиспользованы. Headless-запуск создал изображение меню
и файлы сохранений в доступной папке `/workspace/.star-frontier/data`.

## Здесь не проверено

- Ручной сеанс с физической клавиатурой и мышью: у машины нет дисплея.
- Полноэкранный режим на реальном мониторе: проверен только SDL dummy.
- Прослушивание музыки и эффектов через настоящие динамики.
- Выполнение `launch_windows.bat` на Windows и запуск на macOS. Файл запуска
  проверен чтением; он содержит CRLF, предпочитает Python 3.11, создаёт локальную
  `.venv` и не запрашивает административных прав. Обновлённый запуск устанавливает
  Pygame через `tools/install_dependencies.py`; фактическая установка включённого
  Windows-wheel на Windows пока не проверена.
- Запуск на Python 3.11 и 3.13 отдельно: текущий интерпретатор — 3.12.14.
- Публикация облачного снимка и восстановление в новой задаче.

## Установка на Windows при ошибке сертификата

На предоставленном пользователем снимке первая установка завершилась ошибкой
`SSLCertVerificationError: unable to get local issuer certificate` при доступе
к `pypi.org`. Это сбой проверки цепочки сертификатов HTTPS; отсутствие подходящей
версии Pygame по этому выводу установить нельзя, поскольку список пакетов
не был получен. Установленная на этой машине цепочка сертификатов не исследована.

В проект добавлена установка из официального локального wheel Pygame 2.6.1
для Windows 64-bit / Python 3.11. Она проверяет SHA-256 перед установкой,
использует `pip --no-index --no-deps` и не обращается к PyPI. Ранее созданная
`.venv` подходящей версии переиспользуется. Для других интерпретаторов остаётся
установка через HTTPS с проверкой сертификатов; отключение TLS не применяется.

Эта исправленная процедура ещё не выполнялась на машине пользователя.
Проверки установщика в облачной Linux-среде следует отличать от запуска игры
на настоящей Windows с дисплеем и аудиоустройством.

## Повторяемая облачная среда

В черновике конфигурации сохранены `install_script`, `start_skill` и требование
`STAR_FRONTIER_DATA_DIR=/workspace/.star-frontier/data`. Секреты и дополнительные
сетевые домены не требуются. Сохранение черновика не публикует среду.
Для повторного использования проверьте и сохраните настройки среды, затем
опубликуйте её через интерфейс продукта. Локальные файлы и ресурсы готовы;
живой процесс игры после восстановления следует запустить заново.

В обновлённой версии добавлены 7 тестов установщика; полный набор из 51 теста
успешно выполнен. Настоящий pip в режиме `--dry-run` принял локальный wheel
для целевой платформы Windows x64 / CPython 3.11 с `--no-index --no-deps
--require-hashes`. Это подтверждает совместимость пакета и проверку суммы;
выполнение Windows DLL в Linux не проводилось.
